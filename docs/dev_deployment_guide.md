# Ignis Dev Deployment Guide

This guide documents the automated deployment process for the **Ignis Dev** environment (Vites Server).

| Component | Detail |
|-----------|--------|
| **URL** | `https://dev.vites.iamsorry.in` |
| **Server IP** | `72.62.197.76` |
| **Port** | `8082` (mapped to container port 8080) |

## 🚀 Deployment Workflow

The deployment is fully automated via GitHub Actions: `.github/workflows/deploy-ignis-dev.yml`.

### Triggers
The workflow runs automatically when a **tag** starting with `ignis_dev_v*` is pushed.

```bash
# Example: Deploy version 0.1.2
git tag ignis_dev_v0.1.2
git push origin ignis_dev_v0.1.2
```

### Workflow Steps
1.  **Checkout**: Clones the repository to the runner.
2.  **SSH Connection**: Connects to the VPS using `SSH_KEY`.
3.  **Code Update**: Updates the code in `/opt/ignis/dev/ignis_core`.
    *   *Note*: Handles both fresh clones and existing repos.
4.  **Configuration**: Generates a `.env` file in `/opt/ignis/dev/.env` using GitHub Secrets.
    *   `DB_PASSWORD` is injected from secrets.
5.  **Build**: Builds the Docker image `ignis-server:dev` with the version tag injected via `ldflags`.
    *   **Crucial**: The `VERSION` build arg ensures `/api/version` reports the git tag.
6.  **Deploy**:
    *   Copies `docker-compose-ignis-dev.yml` to `docker-compose.yml`.
    *   **Forcefully** removes old containers (`vites-dev`, `vites-dev-db`) to ensure a clean state.
    *   Starts new containers with `docker compose up -d --force-recreate`.
7.  **Verification**:
    *   Checks `http://localhost:8082/health`.
    *   Verifies `http://localhost:8082/api/version` matches the git tag.

## 🔐 Secrets & Configuration

The following **GitHub Secrets** are required:

| Secret | Description |
|--------|-------------|
| `SERVER_IP` | IP address of the VPS. |
| `SSH_KEY` | Private SSH key for `root` access. |
| `DB_PASSWORD` | Password for the PostgreSQL database. **Must match** the value used when the DB volume was created. |
| `FIREBASE_SERVICE_ACCOUNT` | JSON content of the Firebase service account key. |

### Environment Variables
The workflow generates a `.env` file on the server at `/opt/ignis/dev/.env`:
```env
PORT=8080
GIN_MODE=debug
DB_HOST=db
DB_USER=vites_user
DB_PASSWORD=<injected_from_secret>
DB_NAME=vites_db
ALLOWED_ORIGINS=*
DOMAINS=dev.vites.iamsorry.in
```

## 🛠️ Troubleshooting

### 1. Database Authentication Failed
*   **Symptom**: `vites-dev` container restarts repeatedly; logs show `password authentication failed`.
*   **Cause**: The `DB_PASSWORD` in the secret does not match the password stored in the PostgreSQL volume (`vites-dev-pg-data`).
*   **Fix**:
    1.  Update the `DB_PASSWORD` secret in GitHub.
    2.  **Reset the DB Volume** on the VPS (Warning: Deletes all data!):
        ```bash
        cd /opt/ignis/dev
        docker compose down
        docker volume rm dev_ignis_dev_pg_data
        ```
    3.  Re-run the deployment.

### 2. Version Mismatch
*   **Symptom**: The deployment succeeds, but `/api/version` returns `dev` or an old version.
*   **Cause**: Docker used a cached image layer or failed to inject the `build-arg`.
*   **Fix**: The workflow now includes aggressive cleanup (`docker rmi`, `docker system prune`). Ensure `ignis_core/server/Dockerfile` uses `ARG VERSION`.

### 3. SSH Timeout
*   **Symptom**: The `Deploy to Server via SSH` step hangs for >10 mins.
*   **Cause**: Often caused by waiting for user input or syntax errors in the shell script (e.g., bad variable interpolation).
*   **Fix**: Check the workflow script for unescaped quotes or commands that prompt for confirmation.
